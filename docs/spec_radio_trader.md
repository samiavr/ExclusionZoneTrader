# Exclusion Zone Trader (B42) - 隔離地域外トレーダー 仕様書

## 1. コンセプト＆世界観概要

### 1.1 世界観設定 (Lore & World Context)
* **舞台**: ノックス郡・隔離地域（Knox County / Exclusion Zone）。
* **背景設定**:
  - **隔離の成功と見捨てられた檻**: ノックス州の封鎖線は維持され、隔離線の外側（外の世界）では辛うじて政府・軍・市民社会の文明と経済が保たれている。
  - **インフラ放棄と奪還不能**: しかしノックス郡全域があまりにも広大すぎるため、外の政府も電気や水道のライフライン復旧は放棄。ワクチンや治療法も存在しないため、二次感染を恐れて地上部隊による救出・奪還も不可能とされた。
  - **電波隔離（ジャミング）**: パニック防止の情報統制と外部連携遮断のため、隔離地域全域には軍による電波ジャミングが敷かれている。
  - **秘密周波数 `104.8 MHz`**: 生存者は検問・軍の監視網の隙間を縫う特定の周波数（104.8 MHz）を特定し、外の世界の密輸業者・有志補給部隊と秘密裏に交信する。
* **物理的接触の排除**: 外の人間にとっても地上は極めて危険な死地。そのため、取引はすべて**「上空からのヘリコプターによる超短時間の物資投下（LZ指定・ホバリング投下）」**でのみ成立する。

### 2.1 隔離地域外との無線貿易 (Radio Trading)
1. **周波数チューニング**:
   - HAMラジオまたは高出力トランシーバーを専用周波数（例: 外部民間闇ネット `104.8 MHz`, 軍放出品ネット `92.4 MHz` 等）に合わせる。
2. **取引インターフェース (ISPanel)**:
   - **売却**: ドロップボックス内の特定アイテム（宝石、現金、高純度アルコール、銃器、採集レア品、農作物等）を査定。
   - **購入**: 医療品、弾薬、MRE、特殊工具、建材、B42新規素材などを購入。

### 2.2 ヘリコプター輸送システム (Helicopter Delivery)
1. **補給便の発注と手動投下要請 (アンロード問題回避)**:
   - 取引成立後、数時間（例: 3〜6時間後）でヘリが到着圏内（READY_FOR_DROP 状態）に入る。
   - 到着直前に無線からノイズ混じりの事前通知が届く。
   - **プレイヤーがLZ（50タイル以内）に近づき、「投下要請」を手動で実行した瞬間**にヘリ演出とアイテム投下が開始される。
   - これにより、遠征中に拠点コンテナがアンロード状態（メモリ解放状態）になってアイテムが消滅する問題や、留守中に拠点がゾンビに破壊される事故を完全に防止する。
2. **要請期限とキャンセル**:
   - ヘリ到着圏内に入ってから **48時間** 以内に投下要請を行わなかった場合、注文はキャンセルされ、支払ったクレジットの **半額（50%）** が返金・残りは没収される。
3. **投下・回収（ドロップボックス連携）**:
   - プレイヤーが指定した屋外の「ドロップボックス（コンテナ）」に物資が納品・回収される。

### 2.3 ゾンビ誘引と動的ホード生成（★リポップOFF完全対応）
このシステムの最大のゲームプレイ的価値は**「リポップなし環境における持続的な戦闘・リスク＆リターン」**にあります。

* **課題（通常のリポップOFF環境）**:
  - 拠点の周囲を一度掃討してしまうと、その後ゾンビが寄り付かなくなり、拠点の防衛設備やトラップが無駄になり、ゲームが過疎化・退屈化しやすい。
* **本Modの解決策（ヘリによるゾンビ連行・遠方からの集結）**:
  1. **巨大な音響メタイベント (`WorldSoundManager`)**:
     - ヘリ接近時、広範囲（半径300〜500タイル以上）に大音響を発生させ、未踏地域や街の奥深くにいるゾンビを一斉にプレイヤー拠点方向へ向かわせる。
  2. **範囲外・セル境界からの「連行（スポーン/移動誘導）」**:
     - リポップOFFであっても、「ヘリの飛行ルート上（マップ外や遠方セクター）」からヘリを追いかけてきたゾンビ群が、投下地点周辺に引き連れられて流入するメカニクスを組み込む。
     - これにより、**「交易を行って強力な物資を手に入れる＝必然的に大規模な防衛戦（ウェーブ）が発生する」**という緊迫感あるサイクルを生み出す。

### 2.4 予約キュー型ゾンビスポーン (超巨大セーフゾーン対応)
システム的な強制スポーンによって「プレイヤーが壁で囲んだ拠点の内側」にゾンビが湧いてしまう理不尽な事故を防ぐため、以下の2段構えのスポーンシステムを導入する。
1. **環境判定による即時湧き (小規模セーフゾーン向け)**:
   - ヘリ要請時、現在ロード済みのチャンク（プレイヤー周辺約70マス）をスキャン。
   - **「空きマスであること」「屋外であること」「プレイヤー建築物（壁・床）がないこと」「木（Tree）が生えていると高スコア」** という条件で自然環境を判定し、壁の外側に確実に湧かせる。
2. **チャンクロード遅延湧き (超巨大セーフゾーン向け)**:
   - もしロード済み範囲がすべてプレイヤーの要塞で埋め尽くされている場合、無理に拠点内に湧かせず、ゾンビ数を **「予約キュー（ModData）」** に保持する。
   - プレイヤーが偵察などで移動し、**壁の外側のチャンクが新しく読み込まれた瞬間 (`OnChunkLoaded`)** に、その自然環境をトリガーとして一斉に実体化・進軍を開始させる。

## 5. 拡張仕様：売却システム＆査定ロジック

### 5.1 世界観背景（隔離地域内外の経済格差）
ノックス隔離地域「内」と「外（非隔離地区）」では物の価値が完全に逆転している。
外の世界は物資に困っていないが、**「終末を生き延びた者が隔離地域内で作った一点物」**には
希少価値・コレクター需要・プロパガンダ的意義が生じている。
一方、**「外でも量産できるもの・感染リスクのあるもの」**は買い手がつかない（買取拒否〜捨て値）。

---

### 5.2 売却アイテム査定テーブル

#### カテゴリA：高価値品（スキル係数 × ランダム需要係数 あり）

| アイテム種別 | 具体例 | 買取価値の根拠（世界観） |
| :--- | :--- | :--- |
| **記念品・一次資料系** | 日記、手紙、絵画・落書き、観光グッズ、チラシ、ポスター | 「失われたノックスの生々しい記録」として好事家・歴史家・メディアが高値で争奪 |
| **ハンドメイド衣服・服飾** | 自作のジャケット、シャツ、帽子等（Tailoring スキルで製作） | 「死線で作られた一点物ファッション」として富裕層・闇ブティックへ |
| **ハンドメイド木工家具** | 自作の椅子、テーブル、棚（Carpentry スキルで製作） | 「非隔離地区では手に入らないラスティックアンティーク」として高需要 |
| **ハンドメイド金属製品** | 自作の刃物、工具、装飾品（Metalworking スキルで製作） | 「手鍛造の本物志向ナイフ」としてサバイバル趣味層に人気 |
| **ハンドメイド陶芸品** | 自作の皿、マグカップ、壺（Pottery スキルで製作） | 「隔離地域の土で焼いた終末陶芸」として芸術コレクター需要 |
| **ハンドメイドアクセサリ** | 自作のブレスレット、ネックレス、リング | 「サバイバーハンドクラフト」としてメモリアル需要 |

**査定計算式：**
```
買取額 = 基準価格
        × スキル係数  (製作時のスキルLv: 1〜10 → 係数 1.0〜3.0)
        × 品質係数   (アイテムのCondition: 0〜100% → 係数 0.5〜1.0)
        × 需要係数   (毎ゲーム内24時間ごとにランダム更新: 係数 0.5〜2.0)
```

> **スキル係数の意義**: 裁縫Lv1の粗末な服より、裁縫Lv10の完成度の高い服の方が
> 外の市場で3倍の値がつく。「職人として稼ぐ」というロールプレイ動機を生む。

> **需要係数の意義**: 毎日クラフトして同じアイテムを大量に売れば相場が下がる。
> 需要の波を読んで「今日は服が高い・明日は陶器が高い」という管理ゲームを生む。

---

#### カテゴリB：二値化品目（外では安値 / 買取拒否 または捨て値）

外の世界でも量産可能なもの・感染リスクがあるもの・輸送コストに見合わないものは、
**「送料（ヘリ燃料代）すら賄えない」**という理由で買取を事実上拒否される。

| アイテム種別 | 具体例 | 低評価の理由（世界観） |
| :--- | :--- | :--- |
| **一般銃器・弾薬** | ピストル、ライフル、12ゲージ弾等 | 軍や工場に在庫が溢れており、血液付着品は検疫リスク |
| **工具・ハードウェア** | バール、ハンマー、レンチ、釘等 | ホームセンターにいくらでも在庫がある |
| **嗜好品** | 高純度アルコール、タバコ、自家製ハーブ | 外の工場での大量生産品と競合、感染リスク懸念で買い手が慎重 |
| **燃料** | ガソリン缶（ガソリン入り）、ジェリカン（ガソリン入り）| 精製所が外にあり余剰。感染地域のガソリンは汚染懸念。空き缶は不可 |

> **ゲームデザイン上の意図**: プレイヤーの「とりあえず全部売ればいい」を防止し、
> **何を集めてクラフトし、何を売るか**という意思決定をゲームの中心に置く。

### 5.3 通電ATMによるクレジット換金システム

バニラで死にアイテム扱いされている **クレジットカード・現金** を有効活用できる補完システム。

#### 利用条件
- ATMから半径 **20タイル以内** に通電済みの発電機が存在すること、
  または街の送電網がまだ生きていること（序盤限定の恩恵）。

#### 換金ルート

| ルート | 操作 | 取得クレジット | 備考 |
| :--- | :--- | :--- | :--- |
| **カード引き落とし** | 通電ATMを右クリック → クレジットカードを選択 | 500〜3,000 クレジット（カードの名義残高をランダム判定） | 一度使用すると「使用済みカード」に変化。再利用不可。 |
| **現金デポジット** | 通電ATMに現金（紙幣・小銭）を入れる | 額面の **20%** をクレジットに換算 | 隔離地域外での現金価値は暴落しているためレート悪い |

#### 世界観補足
> 「ノックス封鎖直後、連邦政府は隔離地域内の銀行口座を「行方不明者資産」として
> 凍結した。しかし闇ルートでは古いATMネットワークへのバックドアが残されており、
> 外のブローカーがそのトランザクションを横流しでクレジットに変換してくれる。」

### 5.4 売却フロー（集荷＆配達の統合）

```
① プレイヤーがドロップボックスに「売却品（ハンドメイド品・記念品等）」を入れる
② 無線機で査定リクエスト → 「合計 1,450 クレジット相当です。集荷しますか？」
③ 承認するとクレジットが即時加算（集荷は次回のヘリ便と統合）
④ 補給品を発注してヘリ投下要請を実行
⑤ ヘリ到着時：
   ドロップボックスの売却品を回収（中身が空になる）
   ＋ 注文した補給物資が投下・収納される
```

> **実装上の重要点**: 査定額は承認時点でクレジット加算するが、
> 売却品はヘリ到着（投下要請実行）まで物理的にコンテナに残り続ける。
> ヘリが来る前に売却品を取り出した場合は差額クレジットを回収（ペナルティ）する。

## 6. ショップ拡張：バニラCrate日替わりスポット枠 ＆ CR消費「他に何かないか？」打診システム (Phase 5-D)

* **表示形式**: `アイテム名 x 数量  -  価格 CR` （例: `麻袋(粘土) x 4  -  800 CR`）
* **選出数**: 毎日重複なしで 6品 をランダムピックアップ。
* **自動更新サイクル**: ゲーム内時間の日付変更（毎朝、`getWorldAgeHours() / 24` の更新）時にサーバー側で自動再抽選（ModData `DAILY_DATA_VERSION = 2` でキャッシュを自動刷新）。

### 6.3 B. 配達時のおまけ同封（「おまけしといたぜ！」）

  - 日替わり特売品を発注した場合、輸送ヘリは購入品に加えて、全9大ジャンルのバニラCrateテーブルからランダムに選ばれた「おまけアイテム（+1個）」をドロップボックスに同封。

  - 取引パネル内ログ: `物資投下完了。%s x%s を確認。「おまけしといたぜ！」（+ %s 同封）`

### 6.5 D. CR消費による「他に何かないか？」打診（リロール）システム
* **UI操作**: 取引パネル下部ボタンバーに **`[打診] 他に何かないか？ (50 CR)`** ボタンを設置。
* **動作仕様**:
  1. プレイヤーがボタンをクリック。所持クレジットが 50 CR 未満の場合は実行不可（赤色エラー通知）。
  2. サーバーへ `rerollDaily` コマンドを送信。
  3. サーバー側で 50 CR を消費し、日替わり枠（ModData: `RadioTrader_DailyState`）を即時再抽選。
  4. クライアントへ同期完了パケットを返信。
  5. 演出:
     - 無線ノイズSE（`RadioStatic`）が再生。
     - UIログ欄に「*「他に何かないか？」と無線で尋ねた（-50 CR）。「……待てよ、奥にこんな物資もあったな」*」と表示。
     - 頭上に緑色の HaloText（`+ 別の在庫を確認中...`）を表示。
     - リストが瞬時に最新ラインナップへとリフレッシュ。

### 6.7 大規模ホード化（Mega Horde）システムと緊迫無線演出
* **概要**:
  - 物資投下ヘリ飛来時、低確率（デフォルト 15%）で通常の **2.5倍規模** のゾンビ群がスポーンし、音響誘引半径も **1.5倍（400 -> 600タイル）** へ拡大する危機イベント。
* **サンドボックス設定（`option MegaHordeChance`）**:
  - 1: なし (0%)
  - 2: 低い (5%)
  - 3: 標準 (15%) [デフォルト]
  - 4: 高い (25%)
  - 5: 毎回発生 (100%)
* **緊迫演出とメッセージ分岐**:
  - **接近時（到着10分前・`CMD_HELI_APPROACH`）**:
    - 通常時:
      - 無線: 「投下ポイント接近中。%s 分後に到着する。周囲の熱源多数--警戒を怠るな。」
      - UIログ: 「[!] 投下ポイント接近中。周囲の熱源多数--」
    - 大規模ホード時:
      - 無線: 「投下地点へ接近中。到着まであと%s分。……おい待て、何だこの数は！？ 奴らが異常な密度で集結しているぞ！ 気をつけろ！」
      - UIログ（赤色DANGER）: 「[!] 警告：異常な規模のゾンビの群れが投下地点へ集結中！」
  - **投下完了時（`CMD_DELIVERY_DONE`）**:
    - 通常時:
      - 無線: 「物資投下完了。%s x%s をランディングゾーンに確認せよ。離脱する。」
    - 大規模ホード時:
      - 無線: 「投下完了！ 街中の奴らが集まってきてるぞ！ %s x%s を回収して今すぐそこから離脱しろ！ 離脱する！」
      - UIログ（赤色DANGER）: 「[!] 投下完了！ 巨大ホード発生中！ %s x%s を回収して速やかに退避せよ！」
    - おまけ同封時（大規模ホード）:
      - 無線: 「投下完了（%s x%s）！ 「おまけ（+ %s）も付けたが、生きて帰れよ！」 奴らに囲まれるぞ、急げ！ 離脱する！」
      - UIログ（赤色DANGER）: 「[!] 投下完了！（おまけ: %s） 巨大ホード発生中！ 物資を回収して速やかに退避せよ！」
* **通信・UI改善**:
  - 呼称「イーグル1」を全廃し、パイロットからの直接無線通信トーンに統一。
  - UIログは最新メッセージ追加時に最下部へ自動追従スクロール。
  - 打診（リロール）残高不足エラーを商人台詞化（「おいおい、駄賃くらいくれよ」(50 CR 必要)）。

### 6.8 配達ヘリホバリング時のLZサーチライト照射演出
* **概要**:
  - 物資投下ヘリが LZ（投下地点）直上に到着し、ホバリング（滞空約20分ゲーム内＝約50秒間）している間、上空から地上を照らす強力なサーチライト演出を点灯させる。
* **技術仕様 (`IsoLightSource`)**:
  - **API**: `IsoLightSource.new(x, y, z, 0.95, 0.98, 1.0, 20)` + `getCell():addLamppost(light)`
  - **色と輝度**: 高輝度青白色 (`r=0.95, g=0.98, b=1.0`)
  - **照射範囲**: 半径 20 タイル（LZコンテナおよびその周辺開口部を広くカバー）
  - **トリガー**:
    - 点灯: ヘリがLZ直上に到着（`STATE_HOVERING`）した瞬間に `CMD_HELI_HOVER_START` を全クライアントへブロードキャスト。
    - 消灯: ホバリング終了時（`STATE_LEAVING`）またはヘリ離脱・デスポーン時に `CMD_HELI_HOVER_END` をブロードキャストし、`getCell():removeLamppost(light)` で安全に消灯・破棄。
  - **フェイルセーフ**:
    - 万が一の通信途絶やイベント中断に備え、クライアント側で最大90秒の自動消灯タイマー（OnTick監視）およびプレイヤー死亡時（OnPlayerDeath）の消灯フックを配備。光源の残留を完全防止。

### 6.9 遠隔仮想ホード（Popman）と近接コーンスポーンのハイブリッド配分システム
* **概要**:
  - ヘリ追従ゾンビを「LZ周辺への直接スポーン」だけでなく、未ロードの遠方（135タイル先）から行進してくる「遠隔仮想ホード（`ZombiePopulationManager.instance:createHordeFromTo`）」と組み合わせて配分するシステム。
  - ヘリが遠方から引き連れてきたゾンビたちが、ある者は先駆け、ある者はヘリ到着前後に外周境界から実体化して一気に雪崩れ込んでくる臨場感を実現。
* **サンドボックス設定（`option HeliHordeRemoteRatio`）**:
  - 1: 近接のみ (遠隔 0% / 近接 100%)
  - 2: 近接多め (遠隔 25% / 近接 75%)
  - 3: バランス (遠隔 50% / 近接 50%) [デフォルト]
  - 4: 遠隔多め (遠隔 75% / 近接 25%)
  - 5: 遠隔のみ (遠隔 100% / 近接 0%)
* **動作メカニズム**:
  1. **遠隔仮想ホード**:
     - ヘリ生成時（アプローチ角 `angle`）の LZ から 135 タイル離れた未ロード空間 `(remoteX, remoteY)` を算出。
     - `ZombiePopulationManager.instance:createHordeFromTo(remoteX, remoteY, lzX, lzY, remoteCount)` を実行。
     - Popman ネイティブスレッドが仮想マップ上でホードを行進させ、プレイヤーのロード境界（約60〜70タイル外）に突入した瞬間にエンジンが自動で実体化。
  2. **近接コーンスポーン**:
     - 残りの `directCount` は、ヘリの接近に合わせて（距離 200〜0 タイル）、ヘリ進行方向の 120 度コーン状（半径 35〜65 タイル）から段階的にスポーン。
  3. **自動フォールバック**:
     - 万が一 `ZombiePopulationManager` の API が取得・実行できなかった場合は、自動で近接直接スポーンへ 100% フォールバック。
