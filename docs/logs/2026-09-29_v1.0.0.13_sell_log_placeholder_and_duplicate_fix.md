# 作業ログ: 売却ログの未置換プレースホルダー（%s）および二重表示の完全解消 (v1.0.0.13)

**日付**: 2026-09-29  
**対象コンポーネント**: `RadioTrader_UI.lua`, `RadioTraderMod`, `RadioTraderMod_B42`, `mod`  

---

## 1. 発生していた問題

ユーザーからのゲーム内スクリーンショットにおいて、売却ボタン押下時に以下の2行のログが表示されていた：
```
>売却完了:%s個のアイテムを売却し、 %sCR を獲得しました。
>売却完了: 1 個を売却し、180 CR 獲得。（対象外 11 個はコンテナに残存）
```

- **事象1**: 1行目に変数プレースホルダー `%s` が展開されずにそのまま露出していた。
- **事象2**: 1回の売却アクションに対して完了ログが2行重複して出力されていた。

---

## 2. 原因の調査と特定

1. **`onSellClick` 内に残存していた古いシングルプレイヤー即時処理**:
   - `RadioTrader_UI:onSellClick()` の 485〜493 行目に、過去バージョンで追加された `if not isClient() then ... end` ブロックが存在していた。
   - その中で `tr("UI_RadioTrader_Log_SellSuccess", "Sale complete: Sold items for %s CR.", tostring(soldCredits))` を呼び出していた。

2. **引数不整合による `%s` 露出**:
   - `Translate/JP/UI.json` のキー `"UI_RadioTrader_Log_SellSuccess"` は `"売却完了: %s 個のアイテムを売却し、%s CR を獲得しました。"` と定義されており、**2つのプレースホルダー（個数、獲得CR）** を要求する。
   - しかし上記コードでは引数を1つ（`soldCredits`）しか渡していなかった。
   - 引数が不足していたため、`getText` / フォーマッタ側で置換できず、未展開の `%s` を含んだ文字列がそのまま UI ログに出力された。

3. **二重出力の構造**:
   - 現在のアーキテクチャでは、シングルプレイヤー（SP）であっても `sendClientCommand` 経由で `ServerEngine` が駆動し、処理完了後に正規の `sellSuccess` イベントがクライアントに通知される（v1.0.0.10にて整備済み）。
   - クライアント側（`RadioTrader_UI:onServerNotify("sellSuccess", args)`）が正確な売却個数・獲得CR・対象外個数を受け取って2行目のログ（`UI_RadioTrader_Log_SellSuccessWithLeftover`）を出力していたため、1行目と2行目でログが二重出力となっていた。

---

## 3. 実施した修正

1. **`RadioTrader_UI.lua` (`onSellClick`) のクリーンアップ**:
   - 不要な `if not isClient() then ... end` 即時ログ＆SE再生ブロック、および `local soldCredits` 変数を削除。
   - 売却成功のログ出力と効果音・残高反映は、正規のサーバー通知ハンドラ（`onServerNotify("sellSuccess", ...)` / `ClientBridge`）に一本化。

2. **全環境同期 & 総合ヘルスチェック**:
   - `tmp/sync_dirs.py` を実行し、`RadioTraderMod` から `RadioTraderMod_B42` および `mod` へ完全同期。
   - `scripts/check_mod_health.py` による全21ファイルの静的解析を実施（Critical Errors: 0, I18N Warnings: 0, ALL PASS）。
