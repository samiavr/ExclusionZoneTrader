# 作業ログ: 2026-10-01 (v1.0.0.48) - ヘリ通過遠隔チャンクへの仮想ホード最優先配置 ＆ 実体フォールバック機構

## 1. 概要
- **ユーザーフィードバック・課題**:
  - デバッグ画面（ゾンビ人口分布）の分析により、黄色い点（実体スポーンゾンビ）が「プレイヤー周辺のメモリロード枠（白い四角形）の右上角（境界線ギリギリ）」に集中して出現していることが判明。
  - 原因: PZエンジンでは未ロードの遠隔チャンクには `IsoGridSquare` が存在せず実体配置できないため、遠方探索がプレイヤー側へと後退し、メモリロードされている最外縁（白い枠のフチ）で妥協スポーンしていた。
- **ユーザー提案**:
  - 「遠隔・近接どちらについても基本的に仮想ホード設置で、仮想ホードとして配置できなかったものの一部を実体ゾンビとして配置はどうかな」

## 2. 実施内容

### 2.1 仮想ホード（Popman）最優先発進アーキテクチャ
- `RadioTrader_HeliEvent.lua`:
  - ヘリ接近時（200, 150, 100, 50 タイル地点）、すべてのゾンビを **その瞬間のヘリ現在地 `(heli.x, heli.y)`（遠隔未ロード空間・右上チャンク）** を起点とする `ZombiePopulationManager:createHordeFromTo` で段階発進。
  - ゾンビは画面外・未ロードの右上チャンクから自然に群れを成してLZへ歩行移動し、プレイヤーのロード枠を跨いだ瞬間にバニラエンジンが自動で実体化。
  - これにより、「ロード枠のフチ（境界線）にいきなり黄色い点がポップする」現象を完全に根絶。

### 2.2 実体フォールバック機構
- `RadioTrader_HeliEvent.lua`:
  - `ZombiePopulationManager:createHordeFromTo` が利用できない環境やpcallエラー時のみ、失敗した数（`fallbackDirect`）を実体スポーンキューへ安全に退避。
  - ヘリ到着時（HOVERING）に未スポーンのフォールバック残存数があれば、安全距離（プレイヤー45タイル外＋進入角+/-30度回廊）に実体化。
