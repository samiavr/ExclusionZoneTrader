# 2026-10-20 v1.1.4 Build 42におけるgetAmmoTypeオブジェクト返却およびJava nullハンドリング修正

## 1. 概要と発生した事象
Project Zomboid (Build 42) において、無線機から「無線取引ネットワークに接続（またはドロップボックス査定）」を実行した際、コンソールに以下のエラーが発生してUIの更新・査定処理が停止する不具合が発生した。

```
ERROR: General      f:124419> Lua((MOD:Exclusion Zone Trader (B42) - 隔離地域外トレーダー)).getAmmoPrice> Exception thrown
	java.lang.RuntimeException: java.lang.RuntimeException: bad argument #1 to 'find' (string expected, got nil) at StringLib.findAux(StringLib.java:1106).
STACK TRACE:
	Lua((MOD:Exclusion Zone Trader (B42) - 隔離地域外トレーダー)).getAmmoPrice(RadioTrader_Config.lua:443)
	Lua((MOD:Exclusion Zone Trader (B42) - 隔離地域外トレーダー)).scanInventory(RadioTrader_ItemsTable.lua:3169)

	Lua((MOD:Exclusion Zone Trader (B42) - 隔離地域外トレーダー)).assessContainer(RadioTrader_ServerEngine.lua:219)
```

## 2. 根本原因の解析 (Root Cause)
1. **Build 42におけるアイテム弾種API仕様変更**:
   - Build 41では `item:getAmmoType()` は文字列（例: `"Base.Bullets9mm"`）を返していたが、Build 42では `ItemKey` や `AmmoType` 等のJavaオブジェクトを返す仕様に変更されている（バニラコード `ISInventoryPaneContextMenu.lua` や `ISFirearmRadialMenu.lua` においても `item:getAmmoType():getItemKey()` として呼び出されている）。
   - また、弾薬が設定されていないアイテムや未対応の武器種・マガジンでは Java側の `null` が返却される。
2. **Kahlua（Lua VM）におけるJava null / userdata の挙動**:
   - Java側から `null` や Javaオブジェクトが返却された際、Lua上では `userdata` 型として扱われるため、Luaの真偽値判定 `if not aType` では **truthy（真）** と判定され、`aType == ""` の比較も通過してしまう。
   - その結果、userdata または null ラップオブジェクトが `RadioTrader_Config.getAmmoPrice(aType)` に渡される。
   - `getAmmoPrice` 内で `string.find(ammoType, "^Base%.")` を呼び出した際、Kahluaの `StringLib` は引数が `java.lang.String` であることを要求するため、型検証に失敗して `bad argument #1 to 'find' (string expected, got nil)` 例外をスローしていた。

## 3. 実施した修正 (Fix Implementation)
### (1) `RadioTrader_ItemsTable.lua` (3158〜3175行目)
マガジンおよび銃器の装填弾薬査定において、`item:getAmmoType()` の戻り値を安全に文字列化する処理を追加：
- 文字列型 (`type == "string"`) であればそのまま使用
- オブジェクトで `getItemKey` メソッドを保持していれば `rawAmmo:getItemKey()` を呼び出し
- それ以外は `tostring(rawAmmo)` を取得し、空文字・`"null"`・`"nil"`・`"userdata:..."` の場合は無効値として扱う
- 有効な弾種文字列が得られなかった場合は、アイテムID（例: `9mm`, `45`, `308`, `Shotgun` 等）から安全に既知の弾種にフォールバック

### (2) `RadioTrader_Config.lua` (`getAmmoPrice`)
引数 `ammoType` に対する防御的プログラミングを徹底：
- `type(ammoType) ~= "string"` の場合、`getItemKey` または `tostring` で文字列化
- `nil`・空文字・`"null"`・`"nil"`・`"userdata:"` で始まる不正値の場合は即座にデフォルト弾薬単価（0.2 CR）を返却
- 文字列であることが完全に保証された段階で `string.find(ammoType, "^Base%.")` を実行
