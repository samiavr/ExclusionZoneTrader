# 作業ログ: v1.0.0.35 MRE残骸の完全撤廃とヘリ進入方向コーン状スポーン

## 概要
ユーザーからの以下の2点の指摘・提案に対応：
1. **存在しないMREの生成ルーチンの残骸調査と撤廃**
2. **ヘリ飛来方向を中心とした円錐形・扇形（コーン状）スポーンの実装**
3. **「接近警告の時点でスポーン範囲をロードさせるか？」についての技術的検証と仕様整理**

## 1. 存在しない MRE の調査と修正
- **調査結果**:
  - `RadioTrader_DebugServer.lua`（`cmdForceHeliEvent`）のダミー注文処理において、アイテムID `Base.MRE`（数量3）がハードコードされていた。
  - バニラ PZ B42 には `Base.MRE` は存在しないため、テスト投下時にアイテム生成に失敗する潜在的バグであった。
- **対応**:
  - 実在するバニラアイテムである箱詰め缶詰 `Base.CannedCornedBeef_Box`（数量1、"Canned Corned Beef Box (Debug Delivery)"）へ正式置換。

## 2. ヘリ進入方向の円錐形（コーン状）スポーン
- **課題**:
  従来のスポーンは LZ から全方位 360度に均等に湧かせていたが、「ヘリが飛んできた空路の真下・後方からゾンビを引き連れてくる（追従ホード）」という世界観・演出を再現するため、進入方角のコーン状から押し寄せる仕様へ刷新。
- **実装内容**:
  - `RadioTrader_HeliEvent.lua`:
    - ヘリ生成時の進入角度（`approachAngle`）を記録。
    - 接近中（距離200/150/100/50タイル）および到着時のスポーン要請時に、進入角 `approachAngle` と広がり角 `spreadAngle = 60`（合計120度の円錐形・扇形）をキューへ渡すように改修。
  - `RadioTrader_ZombieSpawnQueue.lua`:
    - `entry.approachAngle` がある場合、進入角を中心とした扇形（±60度）から角度を決定。
    - 有効マス発見時にバッチ生成（2〜6体）を行い、即時スポーン効率を大幅に向上。
    - キュー保存データにも `approachAngle` を保持。
  - `RadioTrader_DebugServer.lua`:
    - デバッグの `cmdForceZombieSpawn`（ホードのみスポーン）でも進入角（ランダム角）を中心とした扇形（±60度）から優先探索・スポーン。

## 3. 「接近警告時点でロードさせる？」への回答と動作仕様
- **PZエンジンの仕様**:
  - PZではプレイヤー周辺（半径50〜70タイル）のみがメモリにロードされ、遠隔地のチャンクをプログラムから能動的にプリロードし続けるAPIは存在しない。
- **本MODでの最適設計**:
  - 接近警告（`APPROACHING` / 到着10分前）が無線で流れた段階でプレイヤーが LZ 周辺へ向かうことで、LZ とスポーン外周マス（35〜65タイル）がプレイヤーの視界範囲として自然に完全ロードされる。
  - ヘリ接近中（距離200〜0タイル）にコーン状から順次スポーンするため、プレイヤーが LZ で待ち構えている方角（ヘリ進入空路側）からゾンビの大群が押し寄せる。
  - 万が一離れた場所にいても、`SpawnQueue` に蓄積され、プレイヤーが近づいた瞬間にチャンク読み込みイベント（`Events.LoadChunk`）でドカンと一気に出現する。
