# 2026-10-03 v1.0.0.57 種回収ルーチンの完全修復（戻り値不整合・pcall安全化・プレフィックス解決・ネスト走査）

## 1. 概要
- **ユーザー報告**: 「種の回収ルーチンが上手くいってない」
- **調査結果**: 査定関数と注文・売却ハンドラにおいて、以下の4つの重大な障害が発生していたことを特定・根本解決した。

---

## 2. 特定された原因と修復内容

### ① `RadioTrader_ServerEngine.lua` (`processTrade`) の戻り値受取バグ 【最重要】
- **原因**: 
  - `RadioTrader_AssessContainer` の戻り値シグネチャは `assessedItems, totalCredits, err, unacceptedCount, unacceptedItems`。
  - しかし `processTrade` 内で `local resCont, totalCr, err, unacc, items = RadioTrader_AssessContainer(player)` と受けており、変数 `items` に第5戻り値（引き取れないゴミ）が代入されていた。
  - その結果、注文時（Trade）にドロップボックス内の下取り品・種が「ゴミ」と誤認され、回収・プール処理が完全にスキップされていた。
- **修復**:
  - `local items, totalCr, err = RadioTrader_AssessContainer(player)` で正しく第1戻り値を受け取るよう修正。

### ② `container.DoRemoveItem` のプロパティチェックによるアイテム削除失敗
- **原因**:
  - PZのKahlua VM（Java-Luaバインディング）では、Javaオブジェクトのメソッドに対して `if container.DoRemoveItem then` とプロパティ存在チェックを行うと `nil` を返す場合がある。
  - そのため `if` も `elseif` もスルーされ、コンテナから物理削除されない現象が発生していた。
- **修復**:
  - `safeRemoveItemFromContainer(container, item)` ヘルパーを新設。`pcall(container.DoRemoveItem)` → `pcall(container.Remove)` → `pcall(container.removeItemOnServer)` を安全かつ確実に実行するよう改善。

### ③ モジュール接頭辞（`Base.`）なし・表記揺れによる種マッチング失敗
- **原因**:
  - `RadioTrader_SeedMapping` は `"Base.CabbageSeed"` のように `Base.` 付きフルIDで登録されているため、渡されたアイテムIDが `"CabbageSeed"` や大文字小文字違いだった場合に `nil` となり査定から漏れていた。
- **修復**:
  - `RadioTrader_ItemsTable_GetSellEntry` において、`Base.` 補完、`Base.` 除去、さらにアイテム名からの自動作物推測スマートフォールバック（二重・三重の照合）を実装。
  - `item:hasTag("base:isseed")` や `DisplayCategory == "Gardening"` のタグ判定も連携。

### ④ ドロップボックス内のバッグ・袋（ネストコンテナ）内の種走査
- **原因**:
  - プレイヤーが種を「紙袋」や「園芸バッグ」などに入れてドロップボックスに投入した場合、コンテナ直下しか見ておらず回収されなかった。
- **修復**:
  - `RadioTrader_AssessContainer` に `scanInventory` を導入し、コンテナ内にあるバッグの中身も再帰的に走査・回収対象に加えるよう拡張（`entry.container` 記録による確実な削除）。

### ⑤ `RadioTrader_UI.lua` (`onSellClick`) のクライアント早期誤判定ブロックの解消
- **原因**:
  - プレイヤーがドロップボックスから少し離れていてグリッドスクエアが未ロードの場合、クライアント側で `container` が `nil` となり「アイテムなし」で早期拒絶されていた。
- **修復**:
  - LZ座標が設定されている場合はサーバー側に判定を委ね、サーバー側で確実に回収させるように修正。
