# 作業ログ: v1.0.0.34 狂気ホード設定の多層フォールバックとスポーン探索プール化

## 概要
ユーザーより「狂気設定（Insane: 150〜200体）にして実行したが、18体しか湧かない。MOD設定が組み込めていないのではないか」との報告を受け、根本原因を特定・徹底対策を実施。

## 根本原因の分析

1. **サンドボックスオプション取得の多重構造とセーブデータ乖離**:
   - Project Zomboid では、既存セーブデータや環境により `SandboxVars.RadioTrader` がテーブルとしてロードされない、あるいはフラットに `SandboxVars.HeliHordeSize` に展開される、または Java API `getSandboxOptions():getOptionByName()` でしか取れないケースが存在する。
   - `RadioTrader` テーブルが見つからない場合、コードは安全策としてデフォルト値 `Medium`（15〜30体）を採用していた。
   - ユーザーが目撃した「18体」は、まさに `Medium`（15〜30体）のランダム抽選範囲の典型値であった。

2. **スポーン候補スクエア探索の打ち切り問題**:
   - `dbg_forceZombieSpawn` の従来のループは `count * 3` 回のランダム探索を行っていた。
   - プレイヤー周辺以外のマス（半径35〜65タイル）は多くが未ロード（`sq == nil`）または障害物・木・室内。
   - 1回あたり 1〜3体ずつしかスポーンしなかったため、500回程度の試行中にロード済みかつ歩行可能なマスにヒットする回数が十数回しかなく、ちょうど18体程度でループ回数上限に達して打ち切られていた。

## 実施した対策

1. **`RadioTrader_Config.lua` の多層フォールバック取得**:
   - `RadioTrader_Config.getSandboxOption(key)` を新設:
     1. `SandboxVars.RadioTrader[key]`
     2. `SandboxVars[key]`
     3. `SandboxVars["RadioTrader." .. key]`
     4. `getSandboxOptions():getOptionByName("RadioTrader." .. key):getValue()`
     5. `getSandboxOptions():getOptionByName(key):getValue()`
   - `getHordeCountRange()` で数値（1〜5 / 0〜4）および文字列（"Insane" 等）の全パターンを完璧に解決。
   - 戻り値として `min, max, hName, rawHorde` の多値を返し、診断・表示を強化。

2. **`RadioTrader_DebugServer.lua` のスポーン探索プール化＆バッチスポーン**:
   - あらかじめ LZ 周辺（および未ロード時はプレイヤー周辺視界外）から「有効な屋外歩行可能スクエア」のプール（リスト）を収集。
   - 収集したスクエア群から `createHordeFromTo` を用いてバッチ（4〜10体ずつ）で高速生成。
   - 150〜200体（メガホード時 375〜500体）であっても数ミリ秒で確実に目標数を達成。
   - スポーン結果通知（チャット/コンソール）に、設定値・目標数・実績数・有効マス数を詳細表示。

3. **デバッグメニュー「現在ステート照会」へのホード設定表示追加**:
   - `HordeCfg: Insane (150-200, raw=5)` のように、ゲーム内右クリックメニューから即座に現在の認識設定値を確認可能に改修。
